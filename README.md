# Shift Ledger

Personal Android companion for a Dispatch driver. Stores earnings, payouts, expenses, mileage, reusable support messages, and weekly net-income goals on the phone. No Dispatch credentials, backend, analytics, or account scraping. The installed app starts with no earnings records and one editable Sunrun support-message example. The supplied earnings history is a test fixture, excluded from the APK.

## First use

1. Install the APK on an Android phone running Android 8.0 or newer. Open the APK from Files and allow that app to install it if Android prompts. This is a development build for personal testing.
2. In **Earnings**, expand **Import Dispatch history → Open** if it is collapsed, then open a PDF, screenshot/image, or text file, or paste the Detailed Earnings table from Dispatch. Android's **Share → Shift Ledger** also accepts a document or text. Set the year shown on the report. Review the extracted text, preview, check amounts and warnings, then save.
3. In **Home**, start a shift while parked. Grant precise location; allow notifications to see the persistent tracking notice. Optionally enter your starting odometer.
4. Pause for personal driving. Resume from the app. End the shift and choose **Shifts → Review times & mileage**. Correct the start/end date and time, break minutes, or mileage as needed. Corrections update totals while preserving the original recording; **Restore recorded times** removes time corrections.
5. Log expenses in **Costs**. Use **Data → Save full backup** regularly and store the file outside the phone. Use CSV for spreadsheets, not for restoration.
6. In **Data → Appearance → Choose colors & fonts**, choose Forest, Ocean, Violet, Rose, Amber, Slate, or **Pure Black** colors, and Modern, Classic, or Mono text. The live preview updates instantly; choices are saved on this phone. System/Light/Dark controls the six colored palettes. Pure Black always uses true `#000000` backgrounds and cards, even in Light mode. **Reset appearance** restores Forest, Modern, and System.
7. Use **Data → Add home-screen widget**, or long-press the phone's home screen and find **Widgets → Shift Ledger**. The widget shows today's earnings, shift mileage/time, and tracking status. Buttons open the appropriate app controls; confirm shift changes in the app. Tap ↻ for a fresh reading.
8. Use **Home → Saved messages** to add, search, edit, or delete reusable support messages. Use `{order}` as the order-number placeholder. Choose **Use message**, fill the number, then **Copy message** and paste it into Dispatch support. **Edit this copy** changes only the outgoing wording, not the saved template. Order detail and rate cards can open the library with an order number filled in.
9. Use **Home → Dollars per mile** or the rates button in **Earnings** for individual orders and daily, weekly, monthly, or yearly totals. Tap a period to see its orders. Home also has Today, This week, This month, This year, and All history filters.

10. Tap **Home → Weekly goal** for your $1,500 Monday–Sunday goal after recorded expenses. Track your progress ring, 25/50/75/100% milestones, daily net chart, pace needed, week streak, achievements, and past weeks. **Edit weekly goal** changes the target starting with the current week; earlier weeks keep their targets.

11. Open **Home → Open fuel & maintenance** or **Costs → Fuel & maintenance**. Vehicle settings default to a 2023 Ram ProMaster, approximately 24 US gallons per the owner's manual, with a nine-bar gauge based on the owner's dashboard description. The capacity is editable. Use **Update bars** to record the dashboard level; this is a dated manual reading, not a live sensor. Add every fill-up with odometer, gallons, total paid, station, optional before/after bars, and full/partial status. Save your first full tank as a baseline and log the next full tank to measure MPG. If you missed a fill-up, check the missing-fill box. Use **Maintenance → Add service** for oil changes, tires, brakes, or custom service, with optional next-service date/mileage.

To update an existing installation, open the new APK and choose **Update**. Version 0.6.1 uses the same app ID and signing key as earlier builds. Existing appearance and work records are retained. It fixes fuel calculations and reorganizes Home, Earnings, and Data. The records database migrates from version 5 to 6 to retain pending fuel gaps. Finish and review any active shift before installing the update. There is no need to uninstall.

The mileage service starts only from the visible app. Background location and notification-reading permissions are not requested. GPS coordinates are processed for distance and discarded; the database stores aggregate miles and fix times, not a route history. Google Play services supplies location updates. GPS quality and battery behavior must be verified on the actual phone before relying on the mileage log.

## What is implemented

- Today, Monday-through-today, month-to-date, year-to-date, and all-history views: earned, paid out, expenses, earnings after recorded expenses, shift miles/hours, gross earnings per shift mile/hour, and earnings per Dispatch order mile.
- A $1,500 default weekly goal after recorded expenses, editable from the goal screen. Home has a progress card; the detail screen has a progress ring, four milestones, a cumulative net-versus-even-pace chart with daily earnings/cost detail, remaining daily pace, consecutive-week streak, 1/4/12-week badges, best recorded week, and history.
- Per-order dollars per mile, plus weighted daily/weekly/monthly/yearly summaries and period-to-order drilldown. Orders can be searched by order number or date.
- Reusable support messages with a title, editable body, `{order}` substitution, search, clipboard copy, optional customization of a single copy, and deletion confirmation. The Sunrun example is added once on a fresh install or upgrade; deleting it is permanent unless restored from backup. All messages stay local until the user copies and pastes one into another app.
- Start/pause/resume/end shifts using a location foreground service. Clear GPS states (finding, tracking, paused, interrupted, disabled, permission missing, or lost), last reliable fix and accuracy, gap flags, persisted active shifts, manual shifts, odometer-assisted mileage correction, and review notes. No reliable fix for 60 seconds triggers a lost-GPS warning.
- Editable completed-shift start/end times and unpaid break minutes. Original timestamps and duration remain in the database and backups. Times use the phone's local timezone and a 24-hour clock; ambiguous daylight-saving times are rejected. Corrections can move a shift into a different date filter.
- PDF, screenshot, and text earnings import with an editable preview, recognized source-text retention, repeated-import protection, conflicts, and undo by import. Manual earnings can be added and removed.
- A home-screen widget with today's earnings, shift miles/hours, GPS state, and shortcuts to the app's shift/import controls. Refreshes after changes, roughly every 15 seconds during tracking, and on Android's periodic schedule (at least 30 minutes between scheduled updates, potentially longer under power restrictions). The last-check timestamp makes stale readings visible.
- Expense categories and notes; deletion requires confirmation.
- Full JSON backup/restore with validation and a preview. Version 6 backups include fuel, gauge readings, maintenance, vehicle settings, and pending fuel gaps; this app also reads versions 1–5. Restore merges missing IDs; existing conflicting records retain their current values. An untouched Sunrun starter message is replaced by its edited version from a backup. Restored active shifts are closed at backup time and marked for review. Messages and goal settings are included in JSON backups, not the financial CSV.
- CSV export with separate record types, quoted fields, formula-prefix protection, and both effective and original shift timestamps in UTC.
- A nine-bar instrument-style fuel gauge with a drawn pump, manual gauge check-ins, editable tank capacity, and an explicit last-reported date. Low reported fuel receives a notice. Nominal remaining gallons use capacity × bars / 9, and nominal range uses that estimate times measured MPG. These are coarse estimates: actual gauge segments may be nonlinear, the reading is not live, and zero bars does not establish zero remaining fuel or a reserve amount.
- Editable/deletable fill-up records with date, odometer, gallons, total paid, full/partial status, missed-fill flag, station, notes, before/after bars, and an expense toggle. Analysis shows gallons purchased, total paid, weighted pump price, weighted full-to-full MPG, measured miles, fuel cost per measured mile, and recent tank efficiency. Select this week, this month, or all history. MPG includes all vehicle driving rather than Dispatch-only miles. Full-to-full intervals include partial purchases after the starting full tank through the ending full tank. The starting purchase is excluded. Missed fills reset the baseline; the next full tank starts a new interval. Analysis periods select complete intervals by their ending date, so intervals may start before the selected period. Same-day stops are ordered by odometer, creation time, and ID; readings must not roll back across dates.
- Oil-change and maintenance history with service, date, odometer, cost, shop, notes, optional next-service mileage/date, and edit/delete. Only the latest record for each service name is checked for due status, using saved odometer readings and today's date. Due status is shown in-app; no scheduled maintenance notifications or manufacturer service intervals are assumed.
- Fuel and paid maintenance can create a linked expense atomically. Editing the vehicle record updates the same expense; deleting it deletes its expense. Linked costs are managed from the vehicle screen. Turning off the expense toggle removes the linked expense while preserving the vehicle log. Previously entered standalone expenses are not automatically matched; remove duplicates manually. Deleting a fill-up marks the next record as missing fuel to exclude the incomplete MPG interval; clear that flag only when the deleted record was a mistake or duplicate. Vehicle settings, gauge observations, fuel, service records, and linked expenses are in version 6 JSON backups. Restore reads versions 1–6, preserves local conflicts and linked financial records together, and rejects a merged fuel chronology with odometer rollback. CSV contains separate FUEL_DETAIL, FUEL_READING, and SERVICE_DETAIL rows; sum EXPENSE rows for costs rather than adding detail amounts again.
- Seven selectable app color palettes (Forest, Ocean, Violet, Rose, Amber, Slate, Pure Black) and three offline Android font families (Modern/sans serif, Classic/serif, Mono/monospace), with a live preview and reset. The six colored palettes support System/Light/Dark; Pure Black always uses black backgrounds, cards, and navigation surfaces. Earnings and goal accents, forms, dialogs, typography, and system-bar appearance follow the choices. Appearance is a device preference and is not part of the records backup. The existing RemoteViews home-screen widget retains its original styling.

## How records are counted

Weekly goals use the phone’s local date and Monday–Sunday weeks. Net equals orders + adjustments + manual earnings − entered expenses, using each record’s own date, matching Home; payouts never increase progress. Future-dated income and costs are excluded until their date arrives. Daily pace divides the remaining net target by remaining calendar days including today, rounded up to the next cent. Costs not entered are not deducted, and no tax or mileage-cost estimate is assumed.

Goal changes are stored with an effective Monday and carry forward; earlier targets remain intact. Weeks before the first custom setting use the $1,500 default. A current week below goal does not break the previous streak until it ends; empty calendar weeks break a streak. Badges and history recalculate after imports, expense changes, deletions, and restores, so later-entered costs can remove a milestone or win. History lists weeks with earnings/cost activity; the best week excludes empty weeks. Goal settings are backed up and conflicting restored goals keep the current value for that effective week.

PDF pages and images are recognized on the phone using a bundled ML Kit Latin text model; no internet permission is included. PDF pages are rendered one at a time. Imports are limited to 25 PDF pages and 40 MB (text files: 2 MB). Images are downsampled to limit memory use. The selected document is copied into temporary app cache while reading, then removed; saved imports retain extracted text, not the original PDF/image. Table word positions are used to reconstruct rows before parsing. Missing decorative dots in payout rows are accepted. Unreadable duration tokens (for example, `Thr` recognized instead of `1hr`) exclude the affected row with a warning; correct the extracted text and preview again. OCR can also misread digits or miss cropped rows, so compare the preview with the original before saving. The actual Dispatch PDF has not been available here; synthetic document tests do not establish accuracy on every report layout.

Orders, adjustments, and manual earnings contribute to earned income. Payouts are cash movements, displayed separately and never added to earnings. Only ORDER rows contribute imported engaged mileage/time; payout miles/time are not counted again. GPS/manual shift mileage is a separate measurement and never added to engaged miles.

Order rates use `(order pay + all linked adjustments) / order engaged miles`. Period rates divide the combined pay of orders with positive, finite mileage by their combined miles; they do not average individual rates. Orders with missing/zero mileage have an unavailable rate and their pay is excluded from the period rate, with counts and excluded pay displayed. Unmatched adjustments and manual earnings are excluded because they have no matched order mileage. Payouts never contribute to rates. Periods group by the original order date, and weeks begin Monday; a later adjustment therefore updates its original order's daily/weekly/monthly rate. This can differ from the Home earnings total, which groups adjustments by their own recorded dates. Whole-shift rates remain separate and use recorded/corrected shift miles, including recorded return trips. These are gross pay rates, not profit after expenses.

In the supplied history, $16 of adjustments has no matching order. The rate view uses $4,153.81 over 1,419.19 engaged miles, or $2.93/mi; earned income remains $4,169.81. Order 2813447 shows $99.50 / 35.01 mi = $2.84/mi. October 2 totals $315.35 / 116.93 mi = $2.70/mi.

Orders use Dispatch order IDs. Adjustments use order ID plus timestamp; amounts are compared for conflicts. Payouts have no unique ID in the supplied report, so the importer fingerprints their date, amount, and reported time/mileage. Two indistinguishable payouts cannot be reliably distinguished; repeated rows are flagged. Changing those payout fields may produce a different fingerprint. Check payouts against the source when reconciling.

Payout rows omit their year. The preview asks for it explicitly and excludes payouts if the order years do not match. Import one calendar year at a time. Rows containing an order ID and timestamp but no mileage/time are inferred to be adjustments; missing adjustment labels produce a warning. Incomplete or conflicting rows are excluded with warnings. The top-level earnings, balance, mileage, and time totals are not individual records and are excluded.

Manual earnings cannot be matched automatically to imported orders. Delete any overlapping manual entries before importing those earnings. The app warns when manual entries are present. Date filters apply independently to order dates, payout dates, expense dates, and shift start dates. Thus a difference between earned and paid amounts is not automatically money owed. Rates become meaningful only when shift and earnings coverage match.

## Build and verify

Tools: Kotlin 2.2.21, Jetpack Compose/Material 3, Room 2.8.4 (SQLite), Fused Location Provider, bundled ML Kit text recognition 16.0.1, PdfRenderer, RemoteViews widgets, Kotlin serialization, Gradle 8.13, Android Gradle Plugin 8.13.2, JDK 17. Compile/target SDK 36, minimum SDK 26.

Open the project in Android Studio with SDK 36 installed, or use:

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Set `JAVA_HOME` to a JDK 17 installation and `ANDROID_HOME` to the SDK, or put `sdk.dir=/your/sdk/path` in local.properties. No API keys are required. Build output: `app/build/outputs/apk/debug/app-debug.apk`. Tests use JUnit, Robolectric, an in-memory Room database, and Compose UI testing.

Native OCR tests are under `src/androidTest` and run with `./gradlew :app:connectedDebugAndroidTest` on a connected test device or emulator running API 29 or newer. An in-process fixture provider in the test APK generates synthetic table screenshots/PDFs; it is not registered with Android or included in the installed app. JVM test workers use `-XX:TieredStopAtLevel=1` to avoid a Zulu JDK 17 C2 compiler crash encountered in Robolectric's instrumented code.

The supplied history fixture checks 27 orders ($4,066.81), 5 adjustments ($103.00), 18 payouts ($4,208.64), 1,419.19 engaged miles, and 1,644 engaged minutes. It is kept under `src/test/resources`, excluded from the APK. Do not publish the repository without removing or replacing personal fixture data.

Keep the development signing key at `~/.android/debug.keystore` if future builds should update this installation in place. A build signed with another key cannot update it. Export a backup before uninstalling; uninstalling deletes app data. A production signing setup can be added later.
